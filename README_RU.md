# XPPN Manager v1.5.0 Alpha — центр управления VPN-нодами

Версия основана на реальном исходном архиве v1.4.0 Alpha (18 октября 2026), а **не** на новом пустом проекте. Сохранены существующие структура БД, протокол подписанных заданий, агент/helper и интеграция с Remnawave. **Боевые VPS автоматически не затрагиваются.**

## Что нового

- **Графитовый интерфейс:** вкладки «Обзор», «Ноды», «Конфигурации», «Логи», «Мониторинг», «Обновления», «Проекты» и «Новая нода». Адаптивная компоновка и улучшенная контрастность.
- **Вход:** логин и пароль, без TOTP на время тестов. Старый пароль Argon2 сохраняется при миграции, прежний аккаунт получает логин `admin`. Для изменения: `docker compose exec manager python -m manager.cli set-password`. Установочная команда для нового менеджера: `python -m manager.cli init`.
- **Сессии:** cookie до 30 дней. Для сохранения входа при обновлениях необходимо сохранить прежний `XPPN_SESSION_SECRET` из `.env`; никогда не генерировать новый секрет при обновлении. Принудительно выкинет только при истечении срока, смене секрета или очистке браузера.
- **Центральные конфиги:** доступны Nginx и два Docker Compose (`nginx`, `nginx_compose`, `node_compose`). Первый импорт с конкретного VPS запускается кнопкой «Первичная загрузка». После этого редактор читает копию в **зашифрованной** БД главного сервера. Кнопка «Сохранить» создаёт ревизию, «Применить» через подписанного агента пишет и проверяет на целевом VPS. Для предотвращения перезаписи ручных изменений сверяется SHA-256 исходного файла на VPS; при несовпадении — отказ. Для Nginx выполняются `nginx -t` и reload; для Compose — `docker compose config -q` и `docker compose up -d`. Предусмотрено восстановление старого файла при ошибке, но проверь работу сервиса вручную после сбоя.
- **История изменений:** 30 последних версий на каждый конфиг; любую можно восстановить в новый черновик (затем отдельно применить).
- **Логи:** Docker remnanode/nginx, journald Docker/helper/remnanode, файлы Xray access/error и Nginx access/error. Хвост ограничен до 300 строк и ~12 KB на выдачу, обновление каждые 10 секунд. Путь логов зависит от установленных сервисов: на некоторых VPS журналы доступны только через Docker. Нельзя выполнять произвольные host shell-команды через веб-интерфейс.
- **Ограничение диска:** подписанная задача `logs.policy` создаёт отдельное `/etc/logrotate.d/xppn-managed` для файлов Xray/Nginx с пресетами 10 MB × 3, 50 MB × 5, 100 MB × 10; есть массовая отправка политики на совместимые ноды. Новые Compose-файлы агента и менеджера ограничивают JSON Docker logs до 10 MB × 3. На **уже работающих** Docker-контейнерах политика JSON-логов применяется только после пересоздания контейнеров по обновлённому Compose; само обновление агента **не** перезапускает VPN.
- **Нагрузка:** CPU, RAM, диск, сеть, uptime; история до 30 дней (с ограничением размера выборки), графики CPU за сутки, неделю или месяц.
- **Настройки:** отдельная вкладка с изменением логина/пароля, статусом Telegram и GitHub update, кнопкой ручного резервного копирования SQLite.
- **Обслуживание:** фоновая очистка завершённых заданий, старой истории и журналов, ежедневная SQLite-копия в `/data/backups` (7–8 дней). При необходимости Telegram оповещения о недоступности ноды/ошибке/свободном диске <10%; настройка через `.env` без передачи токенов на фронтенд.
- **Обновление главного сервера из GitHub:** веб-кнопка отправляет запрос в очередь. На хосте отдельный systemd-обработчик с заранее закреплёнными GitHub URL и веткой (никаких пользовательских shell-команд); скачивает код, создаёт резервную копию volume, обновляет только Manager, проверяет HTTP и при сбое пытается восстановить volume и прошлую версию. Кнопка выключена, пока на хосте не настроен обработчик. Ноды не обновляются этой кнопкой.
- **Репозиторий:** `.gitignore` исключает ключи, .env и базы; GitHub Actions проверяет тесты и JS.

## Обновление уже установленного менеджера v1.4 → v1.5

**Проводить на тестовом VPS.** Сначала сделай snapshot управляющей машины и сохрани копию `/opt/xppn-manager/.env` в безопасном месте. Копирование архива на VPS — отдельный шаг (например, `scp`). Для работы требуется Docker, Docker Compose v2, Python3.

Загрузи `xppn-manager-v1.5.0-alpha-full.tar.gz` на управляющий VPS в `/tmp` и выполни:

```bash
cd /opt/xppn-manager
sudo bash -c 'tar -xOzf /tmp/xppn-manager-v1.5.0-alpha-full.tar.gz xppn-manager-v1.5.0/deploy/install-v1.5.0-full.sh | bash'
```

Скрипт самостоятельно делает резервные копии исходников и SQLite volume в `/root/xppn-manager-backups`, обновляет **только Manager** и выполняет проверку доступности. Пароль и данные сохраняются. Если уже был установлен отдельный механизм автоматических обновлений, сравни его с новым worker до включения. Новые хостовые системные изменения должны применяться явно, не в рамках этой команды.

## Обновить агент на ОДНОМ тестовом VPS

Загрузи тот же архив в `/tmp` непосредственно на **выбранную ноду**. Команда обновляет только XPPN Agent/helper, не трогает Remnawave, Nginx, firewall и SSL:

```bash
sudo bash -c 'tar -xOzf /tmp/xppn-manager-v1.5.0-alpha-full.tar.gz xppn-manager-v1.5.0/deploy/upgrade-agent-v1.5.sh | bash'
```

Перед обновлением требуется снимок VPS. После обновления убедись, что хостовый `xppn-helper.service` и контейнер `xppn-agent` работают. Остальные ноды до проверки не трогай.

## Настройка публичного GitHub репозитория

Репозиторий `chapaayy/Manager` публичный. Не публикуйте реальные секреты и данные клиентов. Код подготовлен к публикации; **не загружай туда .env, персональные SSL-ключи, SQLite или ключи агента.**

```bash
cd xppn-manager-v1.5.0
git init -b main
git add .
git commit -m 'XPPN Manager v1.5.0 alpha'
git remote add origin git@github.com:chapaayy/Manager.git
git push -u origin main
```

После создания репозитория и настройки на **управляющем VPS** read-only SSH deploy key, загрузи в `/opt/xppn-manager` содержимое проекта (если был выполнен архивный апгрейд, скрипт уже перенесён). Затем один раз из директории проекта:

```bash
cd /opt/xppn-manager
sudo bash deploy/install-updater.sh git@github.com:chapaayy/Manager.git
docker compose --profile public up -d --no-deps manager
```

Только тогда кнопка «Обновить» сможет применять новую версию **главного Manager**. Не выдавай GitHub-пользователям и сайту доступ к Docker socket. Убедись, что `git clone` у `root` работает без интерактивного ввода пароля. Перед использованием кнопки сначала проверь обновление на тестовой панели. Не допускай попадания непроверенного кода в закреплённую ветку — host-worker запускается с привилегиями root.

## Ограничения Alpha

- Тесты из архива проходят локально, но реальная работа с твоими VPS, сертификатами, путями к логам, Docker Compose и GitHub-деплоем **не проверена**.
- Xray transport-профили Hysteria 2, XHTTP, REALITY редактируются в Remnawave, а не через центральный Nginx/Compose редактор.
- История конфигов существует на управляющем сервере, поэтому его зашифрованную БД и `XPPN_DATA_KEY` обязательно сохранять вместе.
- При высокой нагрузке непрерывное чтение логов от множества нод лучше заменить серверным потоковым сервисом; текущая версия опрашивает выбранную ноду.
- Telegram-оповещения требуют отдельного бот-токена/ID; без них функция отключена.
- Скрипты и web-update не устанавливают новое приложение на чистый VPS автоматически и не изменяют действующие ноды, пока ты явно не запустишь команду.
