# XPPN Manager 1.8.0 Alpha — установка одним файлом

Вместо десятка команд используется **один `install.sh`**. Он устанавливает и настраивает главный сервер XPPN Manager с Caddy, Docker, SQLite, учётной записью и обновлениями. Файлы действующих VPN-нод и Remnawave не меняются.

## Установка на главный VPS

На Ubuntu/Debian с доступом в интернет, доменом на IP сервера и открытыми портами 80/443:

```bash
curl -fsSL https://raw.githubusercontent.com/chapaayy/Manager/main/install.sh -o /tmp/xppn-install.sh && sudo bash /tmp/xppn-install.sh
```

При первом запуске автоматически откроется редактор `/opt/xppn-manager/.env`. Заполни **только три поля**:

```dotenv
XPPN_DOMAIN=manager.example.com
XPPN_ADMIN_USER=admin
XPPN_ADMIN_PASSWORD=YOUR-PASSWORD
```

Сохрани файл (`Ctrl+O`, `Enter`, `Ctrl+X` в nano). Установщик сам:
- Сгенерирует `XPPN_SESSION_SECRET` и `XPPN_DATA_KEY` или **сохранит существующие**.
- Установит Docker и Compose при необходимости (на поддерживаемых Debian/Ubuntu).
- **До остановки старого Manager** проверит и соберёт новый образ.
- Создаст резервную копию базы и исходников перед заменой.
- Автоматически создаст учётную запись с Argon2-хешем пароля, без ручной команды `init`.
- Уберёт открытый пароль из `.env`, оставив его хеш в SQLite.
- Запустит Manager, Caddy и таймер обновлений, проверит локальный API.

Если запуск без интерактивного терминала, установщик создаст `.env` и остановится: отредактируй его и **повтори ту же команду**.

## Повторная установка и ремонт

Та же команда повторно скачивает текущую версию, не требует вводить новые секреты и не меняет администратора, если `XPPN_ADMIN_PASSWORD` оставлен пустым. Чтобы сменить пароль, введи новый в этом поле (можно даже короткий, но для публичной панели используй сильный), снова запусти установщик — старый пароль сменится, поле после успеха очистится.

**Не удаляй `.env` или Docker volume.** `XPPN_DATA_KEY` используется для шифрования ключей нод, `XPPN_SESSION_SECRET` сохраняет вход после обновления.

## Обновления на сайте

Кнопка «Обновить» уже настраивается установщиком. Обработчик берёт код только из `chapaayy/Manager` (ветка `main`), собирает новую версию **до** остановки старой, затем делает резервную копию и переключает Manager. Если сборка не удалась, старый сайт продолжает работать; если проблема после переключения, скрипт пытается восстановить предыдущую версию. Ноды автоматически не перезапускаются.

## Данные и безопасность

- `/opt/xppn-manager/.env` — настройки (права 600).
- Docker volume `xppn-manager_manager-data` — база SQLite и данные нод.
- `/root/xppn-manager-backups` — резервные копии миграций.
- `/opt/xppn-manager-updater` — служба обновления.

Старые установочные скрипты v1.1–1.5 удалены из новой версии, но доступны в истории Git. Файлы `legacy`, `bootstrap` и `agent` нужны для действующей функции установки нод и сохранены.

**Ограничения:** это Alpha, полноценная проверка на твоём VPS ещё не проведена. Перед первым обновлением сделай snapshot сервера. Репозиторий публичный — в GitHub нельзя отправлять реальные `.env`, ключи или базы. Длина администраторского пароля не ограничена 16 символами: даже `admin` допустим для локального теста. Важно: лимит неудачных попыток входа отключён, поэтому на публичном домене `admin/admin` опасен — доступ лучше ограничить по IP/VPN, затем сменить пароль. Обновлятор запускает доверенный код `main` с root-правами, поэтому защищай права записи в репозиторий.

## Интерфейс v1.6.1: чёрная тема и конфиги прямо в браузере

В интерфейсе появилась полноценная вкладка **«Конфигурации»**. Также в каждой карточке VPS есть кнопка **«Открыть конфиги»**, а из подробностей ноды доступна вкладка «Конфиги».

Выбери VPS и файл: Nginx nginx.conf, Nginx Docker Compose или Remnawave Node Docker Compose. При первом открытии Manager **автоматически и только для чтения** импортирует существующий файл с доступной ноды (если новый XPPN Agent поддерживает команды config.read/config.write). Затем появится многострочный редактор: изменяй текст прямо в браузере, сохрани черновик на главном сервере, после проверки нажми «Применить к ноде». Сохранение **не изменяет** файл на VPS; применение делает резервную копию, проверяет конфигурацию и может перезапускать сервисы.

Новые функции: подсветка несохранённых изменений, Ctrl+S (сохранить), Tab (отступ), предупреждение о закрытии без сохранения, история версий, статусы и подсказки для отключённых VPS/старых агентов.

**Важное ограничение:** конфигурация Xray inbound, TLS, VLESS, Hysteria, Reality находится под управлением Remnawave — её здесь редактировать нельзя, чтобы не нарушить работу панели. Поддерживаются только три перечисленных файла на VPS. Если редактор не появился, проверь, что нода онлайн, у неё обнаружен файл и агент поддерживает config.read/config.write. Новая версия Manager не обновляет старые агенты автоматически.

Тема теперь построена на чёрном фоне, с контрастными серыми поверхностями, белыми основными действиями и явным состоянием элементов на ПК и мобильных устройствах. Версия JS/CSS закреплена параметром `?v=1.6.1`, чтобы не оставались закэшированные старые стили.



## Интерфейс v1.7: библиотека и отдельные пресеты

- **«Конфигурации»** — библиотека файлов на главном сервере. Можно создать `nginx.conf`, Nginx Compose или Remnawave Compose с нуля, не подключая VPS, открыть/изменить/удалить их, или скопировать содержимое из редактора конкретной ноды. Файлы хранятся только в SQLite как Fernet-encrypted значения (используют существующий `XPPN_DATA_KEY`).
- **«Пресеты»** — отдельная страница, на которой можно собрать пользовательский набор из **одного файла каждого поддерживаемого типа**, сохранить название/описание, редактировать и удалять набор без удаления самих файлов. Пресеты ссылаются на сохранённые файлы; после обновления файла набор использует его актуальную сохранённую версию.
- Кнопка **«Добавить в пресет»** в библиотеке открывает конструктор с выбранным файлом.
- Кнопка **«Вставить файл из библиотеки в черновик ноды»** не меняет VPS сама по себе: перед вставкой должен быть считан существующий конфиг соответствующего типа, а после вставки требуется отдельно сохранить черновик и подтвердить применение. Действующие проверки `remote_sha`, история и проверки Nginx/Compose сохранены.
- **Навигация**: отдельные «Конфигурации» и «Пресеты», «VPN-проекты» остались самостоятельным разделом; боковая панель сворачивается до иконок и запоминает состояние в браузере.
- **Макет**: рабочее пространство занимает всю оставшуюся ширину, на ноутбуке и телефоне перестраивает колонки; иконки Lucide (ISC, лицензия `manager/static/LUCIDE_LICENSE.txt`) локально включены в интерфейс.
- Существующие значения `.env`, БД, логин, конфиги и агенты не удаляются при миграции. Добавляются три небольшие таблицы SQLite.

**Ограничение:** сейчас библиотека покрывает именно типы файлов, которыми безопасно умеет управлять агент (`nginx`, `nginx_compose`, `node_compose`). Содержимое inbound Xray редактируется через Remnawave. Сохранение пресета не инициирует никаких операций на нодах. Интерфейс создан в исходниках и проверяется CI, но пока не проверен визуально на твоём реальном сайте.



## v1.8.0 Alpha — первый VPS без путаницы в проектах и inbound-ах

**Приоритет релиза — работоспособное добавление первой ноды.**

Мастер теперь использует **один основной VPN-проект (ID `default`)**, скрывая выбор нескольких панелей; данные других проектов и их шаблоны не удаляются. Три режима установки сохранены: полная установка (Nginx + Remnawave + агент), только Remnawave Node + агент, только управляющий агент.

- При первом выборе `node` или `full` мастер предложит **один раз** указать HTTPS-адрес основной Remnawave, её API-токен и **реальный исходящий IPv4**. Затем он вызывает API панели, получает ключ ноды, показывает профили и их inbound-ы и сохраняет выбранные идентификаторы как общие настройки проекта. **Не выбирай всё автоматически, если в профиле содержатся ненужные inbound-ы**. Дальнейшие VPS используют сохранённое состояние.
- При выборе **«Только управление» панель Remnawave и inbound-ы не требуются**; установится только управляющий агент.
- Шаблон установки выбирается внутри выбранного режима, и переключение режима не должно самопроизвольно возвращать старый тип из проекта. Другие проектные шаблоны остаются в БД на будущее.
- Во втором шаге только основные поля VPS, плюс страна и домен (домен требуется для полной установки). Версия Remnawave, политика логов и специальные настройки спрятаны в «Дополнительно».
- Перед установкой остаётся обязательная сверка отпечатка SSH-ключа через консоль провайдера. **После подтверждения** выполняется отдельная *только читающая* SSH-диагностика ОС, архитектуры, свободного места, присутствия Docker и слушающих портов 80/443/2222. При конфликте портов установка конфликтующего компонента не запускается, пока проблема не исправлена.
- Сам SSH bootstrap, регистрация через API, запись логов и проверка телеметрии сохранены. Если API возвращает пустой список inbound-ов в кратком представлении профилей, менеджер дополнительно запрашивает данные профиля.
- Внешний многорегиональный мониторинг блокировок IP пока **не реализован**: для него нужны измерения из нескольких независимых сетей и внешние тестовые агенты. Он не должен влиять на установку первой ноды.

**Безопасность**: не передавай API-токены и пароль VPS в переписку/скриншоты; они обрабатываются на главном сервере и не выводятся в интерфейсе после сохранения. Для полного режима не отключай проверку свободных портов и подтверждение чистого VPS.

**Статус**: CI проверяет исходники и имитированную SSH/Remnawave-последовательность, но первая настоящая нода на твоём хостинге до сих пор не была установлена и проверена. Работоспособность конкретной инфраструктуры будет подтверждена только реальным тестовым VPS.
