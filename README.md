# XPPN Manager 2.3 — один центр управления Remnawave

Новая автономная кодовая база без VPN-проектов и нескольких панелей. Старый XPPN v1 не удаляется. Развёртывание на отдельном чистом VPS теперь можно **запустить из браузера**, но полноценное подключение на реальном VPS ещё требует эксплуатационного тестирования.

## Обновление установленного менеджера

Открой свой HTTPS-домен Manager → **Обновления → Проверить → Установить**. Веб-панель отправляет запрос отдельной root-owned службе: та сохраняет базу/секреты, обновляет фиксированную ветку GitHub, пересобирает контейнер, проверяет HTTP и пытается восстановить предыдущий код при ошибке. SSH-пароль VPS не хранится в базе. Для первой настройки системы обновлений есть однократный скрипт v2/activate-web-updates.sh.

## Библиотека Xray и установочные пресеты

Вкладка **Конфигурации** разделена на «Xray» и «Серверные конфиги». В библиотеку добавлен Direct Xray JSON; существующий Bridge Xray JSON сохранён. На первом запуске обновления автоматически создаётся новый Direct-пресет (Nginx + два Docker Compose + Xray). Существующий стандартный Bridge-пресет получает назначение «Мост», но его правки не перезаписываются. Содержимое каждой карточки хранится в зашифрованной базе Manager. При выборе пресета установщик использует сохранённые файлы, а не скрытый hardcoded Xray.

**Direct:** один VLESS TLS inbound 443 с fallback 8080, прямой выход, роль «обычная» или «выходная».  
**Bridge:** два VLESS TLS inbound 443/8443; пока не указан реальный выходной сервер и не развёрнут маршрут, весь VPN-трафик намеренно блокируется. Это безопасная базовая установка, **не готовый рабочий транзит**. Выходные направления добавляются отдельным этапом. Никакие существующие ноды и Remnawave-профили автоматически не меняются.

В мастере новой VPS необходимо выбрать установочный пресет и проверить предпросмотр Xray/Nginx. Перед установкой Manager проверяет роли, ограничивает опасные правки Docker Compose и фиксирует зашифрованный снимок выбранных конфигураций: последующие изменения библиотеки не затрагивают уже запущенную установку. Изменённые Compose-файлы допускаются, только если не меняют сервисы, изображения, сетевые порты, тома и привилегии. В старых прерванных установках без снимка сохраняется прежняя логика восстановления.

## Единое управление нодами и первый TLS-статус

В боковом меню теперь **одна вкладка «Ноды»**. Карточки обычных и мостовых серверов открывают полноширинное рабочее пространство конкретной VPS: обзор состояния и агента, Docker/службы, логи, TLS, конфигурации и действия управления. Прежние отдельные пункты меню «Агенты VPS» и «Сертификаты нод» убраны; их операции доступны внутри ноды. Технические команды остаются через существующий ограниченный HTTPS Agent, не через SSH.

После того как Remnawave подтвердила готовность новой ноды, менеджер **сразу ставит первую проверку сертификата в очередь агента**. Первый heartbeat готовой ноды также гарантирует постановку задания, если его ещё не было. Повторные heartbeat не дублируют уже поставленную проверку. Пока агент выполняет проверку, интерфейс сообщает «Проверяется»; срок действия и успешный статус показываются только после подтверждения агентом. Последующие проверки по-прежнему периодические, раз в 6 часов. Приватные ключи остаются только на VPS.

## Новые страницы

- **Конфигурации** — только полноширинный каталог файлов, поиск, отдельная кнопка создания. Просмотр и редактирование открываются в диалоговом окне.
- **Пресеты** — только каталог наборов, редактирование/создание в отдельном окне.
- **Ноды** — топология, список VPS, детальная страница каждой ноды с агентом, TLS, Docker, логами, конфигами и управлением.
- **Настройки** — одна Remnawave: HTTPS-адрес, API-токен, необязательный Caddy/MFA API key, исходящий IPv4 для защиты порта Node 2222.
- **Обновления** — штатное обновление из веб-панели.

Если библиотека была пустой или неполной, добавляются образцы: **Xray Bridge VLESS TLS**, **nginx.conf**, **Nginx Compose**, **Remnawave Node Compose**, плюс один стартовый пресет. Xray Bridge основан на пользовательском рабочем примере RUS1 → DE1, но UUID удалён. Файлы Nginx и Docker основаны на legacy XPPN installer. Это **исходные шаблоны**, а не подтверждённые копии файлов на работающих VPS. Файлы, изменённые или удалённые пользователем, не перезаписываются/не восстанавливаются на каждом старте.

## Минимальная безопасная настройка новой VPS

После **успешного запуска** Remnawave Node установщик запускает необязательный скрипт `v2/data/node-baseline.sh` **только на чистом VPS при новой установке**. Скрипт не редактирует SSH, Docker, конфиги Xray, действующую Remnawave и не меняет политику firewall. Ошибка дополнительной настройки не останавливает работающую VPN-ноду.

- **BBR/FQ:** только `net.ipv4.tcp_congestion_control=bbr` и `net.core.default_qdisc=fq` при поддержке ядра. Прежние значения сохраняются в root-only файле `/etc/xppn-baseline-previous`; проверка результата и попытка отката при ошибке. Не перезапускаются интерфейсы и действующие соединения. Дополнительный TCP tuning не применяется.
- **Fail2Ban:** только `sshd` с `backend=systemd`, 6 попытками за 10 минут, баном на 1 час. SSH-порт берётся из `sshd -T`, текущий IP установочного SSH-сеанса и IP панели исключаются из блокировок. При неизвестном IP администратора или существующем Fail2Ban автоматическое управление пропускается. Проверяется `fail2ban-client -t` и состояние `sshd`; при ошибке созданная конфигурация удаляется. Nginx и VPN-клиенты не банятся.
- **Firewall:** неизменен. Остаётся ранее установленное ограничение доступа к API Node 2222 по IP Remnawave. Никаких `ufw enable`, глобальных DROP, переписывания Docker или правил SSH.
- **Логи:** отдельная ротация Nginx, не затрагивающая существующие Docker/Xray logrotate; 7 архивов, 20 МБ.
- **Мониторинг:** Agent v1.2.0 сообщает счётчики сети через обычный heartbeat, без дополнительного открытого порта. На странице ноды «Сеть и защита» можно выполнить **только чтение** текущих BBR/FQ, Fail2Ban/SSH jail, управляемого правила 2222 и ротации. Скорость RX/TX рассчитывается по разнице двух замеров на активном интерфейсе; bytes, retransmits и drops **накопительные**, их нельзя считать скоростью или процентом потерь.

Уже установленные VPS не изменяются обновлением Manager. Для диагностики новой функции на старых нодах потребуется отдельное безопасное обновление Agent; его нельзя подменять SSH-операциями без подтверждения. Проводить тесты изменений сети сначала на чистой RUS10, а не на рабочих нодах.

## Удаление нод без очистки VPS

**Ноды → Управление** теперь открывает удаление только из Manager и/или через Remnawave API. SSH, Agent, Docker, Nginx, Certbot и сама VPS не затрагиваются. Поддерживаются варианты:

- удалить только запись из Manager (регистрация в Remnawave остаётся);
- удалить ноду из Remnawave и Manager, сохранив профиль;
- удалить ноду из Remnawave, её отдельный Manager-owned Xray Config Profile и запись в Manager.

Менеджер сначала проверяет UUID и привязки через API. Если профиль общий, он перечисляет другие ноды, по умолчанию сохраняет профиль и требует ввода точного названия плюс отдельного подтверждения для удаления общего профиля. Важно: удаление общего профиля может нарушить VPN-подключения **других нод** — панель их настройки автоматически не исправляет. Если имя профиля изменилось или назначение ноды нельзя проверить, автоматическое удаление профиля блокируется.

Сбой API оставляет локальную запись для повторной попытки. Стадия прежнего удаления `finalize_ack` завершается новым способом без повторной отправки команд VPS. Старые HTTP-маршруты полного удаления VPS отключены (410); при запуске менеджера ранее поставленные в очередь задания очистки отменяются. Задания, уже выполняющиеся на удалённом агенте, автоматически остановить нельзя — их состояние следует проверить отдельно.

## Первый VPS: реальная установка

Кнопка **Ноды → Добавить VPS** открывает пошаговый мастер:

1. Название и код сервера, страна, роль (обычная или выходная), IP, SSH root пароль и порт, домен, исходящий IPv4 Remnawave.
2. **Проверить**: прочитать SSH host fingerprint, проверить пароль и root, ОС Ubuntu/Debian, свободный диск, совпадение DNS A с VPS, порты 80/443/2222 и отсутствие уже установленных /opt/nginx и /opt/remnanode. До подтверждения сервер не изменяется.
3. Сверить SSH fingerprint с консолью провайдера, изучить предпросмотр Xray/Nginx и **явно подтвердить чистую установку**.
4. Установщик, при подтверждении, выполняет изменения **на целевой VPS под root**: пакеты Docker/Compose, Certbot, Nginx с fallback 127.0.0.1:8080, Let's Encrypt через HTTP-01, Remnawave Node 3.4.1, ограничение управляющего TCP/2222 исходящим IP панели, логротейт и автозапуск. Нужны публично доступные 80/443 и домен с A-записью на VPS.
5. Менеджер запрашивает node SECRET_KEY у Remnawave, создаёт отдельный Xray Config Profile для VLESS TLS RAW, используя локальные пути keyFile/certificateFile к TLS-файлам на VPS (без передачи PEM), и регистрирует Node через API. UUID и сертификаты никогда не выводятся в предварительный просмотр.
6. Статус **registered** означает только, что API подтвердило регистрацию, **не гарантию работающего Xray или доступности клиентов**. До объявления полноценной готовности необходимы проверка статуса панели, Hosts/Internal Squads и реальная проба подключения.

**Важные ограничения**: установка на действующие VPN-узлы запрещена; мостовые изменения пока только dry-run, без live apply. Для первой установки поддерживаются ordinary/exit (VLESS TLS direct), а вход RU Bridge устанавливается лишь после реализации синхронизации принимающей стороны. Глубокая проверка IP из регионов РФ отдельно не реализована. Автоматический rollback удалённого VPS пока **не готов**: при неудачной регистрации может остаться частично установленный сервер. Не запускай повторную установку поверх него без проверки. Ни один реальный VPS не использовался для интеграционных тестов — сначала испытывать только на пустой тестовой машине.

## Файлы проекта

- v2/app.py, v2/storage.py — API, одна SQLite база и статусы.
- v2/remnawave.py — HTTPS API адаптер к единственной Remnawave.
- v2/template_engine.py — рендеринг Bridge и добавление направлений с diff.
- v2/vps_install.py, v2/data/remote-install.sh — SSH проверка, supervised bootstrap, Nginx/TLS/Node, создание профиля.
- v2/bundled.py, v2/library.py — образцы, пресеты и зашифрованная библиотека.
- v2/static/ — новый интерфейс и мастер VPS.
- tests_v2/ — тесты генерации, авторизации, базы, сценариев обновления и установщика (без обращения к настоящим серверам).

## Обновление с v1

Перезапись прежней SQLite/сервисов v1 запрещена. Для переноса только одной Remnawave есть read-only мигратор v2/migrate.py, старые ноды не переносятся. Домен, ключи и учётные данные v2 сохраняются при обновлениях.
