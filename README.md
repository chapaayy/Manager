# XPPN Manager 2.0 — чистая архитектура

**Изолированная предварительная сборка, НЕ замена рабочей v1.** На этой ветке существует одна Remnawave, библиотека конфигов и безопасное планирование мостов. Установка на VPS и изменение действующей панели пока заблокированы.

## Принципы

- Одна Remnawave, одна запись настроек в SQLite. Нет VPN-проектов или нескольких панелей.
- Ноды с кодом, страной, доменом и ролью: обычная, входная или выходная.
- Мост объединяет входную ноду с одним или несколькими выходами; карточка раскрывается списком.
- Xray, Nginx и Compose лежат в зашифрованной библиотеке, пресеты объединяют файлы.
- Xray-шаблон сохраняет структуру работающего VLESS TLS RAW, умеет дополнять существующий JSON **только новыми** inbound, outbound и routing-правилом; остальное не перезаписывается.
- Каждый план генерируется с redacted diff, уникальным портом и проверенными ссылками на теги. UUID скрываются. Подтверждение плана НЕ означает применение.

## Реализовано

Авторизация, ограничение числа ошибок, HttpOnly SameSite cookie, CSRF, отдельная SQLite БД и Fernet-шифрование. Настройка единственной Remnawave и read-only API-проверка профилей с HTTPS и pinned DNS. Записи нод, вложенные мосты, импорт копии текущего Xray, создание и утверждение черновика для нового выхода, предпросмотр JSON и diff, библиотека конфигов, пресеты и адаптивный чёрный интерфейс с локальными Lucide-иконками.

## НЕ реализовано

- SSH-установка XPPN Agent, Docker и Remnawave Node на новый VPS.
- Запись/создание Xray Config Profiles в действующей Remnawave.
- Синхронизация UUID и входных подключений на стороне EU-сервера, Hosts и Internal Squads.
- Автоматическая публикация, Xray run -test на рабочем VPS и откат.
- Проверки доступности IP из разных российских и зарубежных сетей.

**Ни одна кнопка в v2 не запускает установку или изменение на VPS.** Это реальный автономный прототип с БД, но не завершённая production-система.

## Запуск отдельно от v1

Если репозиторий уже клонирован на ветке v2, запусти:

    bash v2/preview-install.sh

Docker и Compose должны быть установлены. Превью работает на 127.0.0.1:8790 в отдельном контейнере, с отдельным томом и секретами. Для VPS используй SSH-туннель с локального ПК:

    ssh -L 8790:127.0.0.1:8790 root@YOUR_MANAGER_VPS

Затем открой http://127.0.0.1:8790. Для локального туннеля cookie может быть Secure=0; для публичного HTTPS нужно включить Secure=1 и настроить TLS.

## Структура

- v2/app.py — авторизованный API одной панели, без VPN-проектов.
- v2/storage.py — единая SQLite DB, зашифрованные конфиги и черновики.
- v2/remnawave.py — read-only API-adapter Remnawave.
- v2/template_engine.py — генератор мостов и добавление выхода без изменения исходного JSON.
- v2/service.py — построение планов с redacted diff.
- v2/library.py — отдельные конфиги и пресеты.
- v2/static — интерфейс, собственный JavaScript и локальные SVG Lucide.
- tests_v2 — проверки API, шаблонов, безопасности и неизменности исходных конфигов.

## Ограничения шаблона

Первый выход использует TCP/443 и /8443, второй получает TCP/8444 (далее свободные 8445...). Это отдельные маршруты, не балансировка. Нынешняя логика строится под VLESS TLS RAW, fallback и существующие RU-фильтры. Для Hysteria2, Reality, цепочек с другими транспортами и балансировки нужны самостоятельные проверенные шаблоны.

## Переход с v1

Старые /opt/xppn-manager, .env и SQLite БД не трогать. В этой фазе не выполняется импорт старых токенов и нод. Для перехода понадобится отдельная миграция с резервной копией, тестовым сервером, проверенным применением и откатом.
