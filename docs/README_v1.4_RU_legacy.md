# XPPN Manager v1.4.0 Alpha — компоненты VPS и интерфейс

## Что нового

- Вместо старой плоской страницы управления — карточка **«Компоненты»**. Фактическое состояние читается из телеметрии агента: наличие файлов Compose и контейнеров `remnanode` / `nginx`. Выбор первоначального пресета НЕ считается подтверждением установки.
- Не установлены Nginx/Remnawave — вкладки и кнопки отсутствуют. Дополнительно серверное API отвергает действия для несуществующих сервисов (`409`), даже если вызвать его вручную. Offline/устаревшая телеметрия блокирует изменения.
- Agent-only VPS можно расширить: **Remnawave Node** через Secret Key и исходящий IPv4 панели из VPN-проекта; или **полный TLS + Nginx стек** только если на VPS ещё нет установленной ноды/Nginx и выбран TLS + Nginx шаблон этого же проекта. Установка полного стека использует прежний Bash installer (проверка обязательна). При добавлении компонента уже подключённый XPPN Agent не устанавливается заново.
- Аккуратное **обновление/пересоздание Remnawave Compose**. Полный сброс и уничтожение данных/контейнеров намеренно не доступны: на старых VPS нельзя гарантированно отличить файлы XPPN от чужих.
- Hysteria 2, XHTTP, REALITY — профили Xray внутри Remnawave, а не отдельные контейнеры. Управление существующим inbound (PATCH ноды) и автоматическая установка/смена этих профилей **ещё не реализованы**. Для них нужно выбирать соответствующие профили в панели Remnawave. Не считай выбранный шаблон автоматически применённым.
- Проекты и шаблоны перегруппированы: формы редактирования скрыты за раскрывающимися секциями. Обновлены внешний вид, адаптивность, состояния и читаемость задач.
- Список доступных функций `helper` теперь включается в его telemetry; команды несуществующих функций для старых агентов не предлагаются/блокируются.

## Обновление центрального Manager

Загрузите полный архив `/tmp/xppn-manager-v1.4.0-alpha-full.tar.gz` на управляющий VPS. Рекомендуется snapshot управляющего VPS.

```bash
cd /opt/xppn-manager && tar -xOzf /tmp/xppn-manager-v1.4.0-alpha-full.tar.gz xppn-manager-v1.4.0/deploy/install-v1.4.0-full.sh | bash
```

Скрипт делает резервные копии исходников, `.env` и отдельного Docker volume с SQLite и обновляет только Manager, **не трогая ноды**. После обновления можно обновить страницу (Ctrl+Shift+R).

## Обновление XPPN Agent на существующем тестовом VPS

Не нужно удалять сервер в Manager или повторно вводить SSH-пароль. Перед запуском сделайте snapshot целевого VPS. Загрузите **тот же полный архив** на конкретный целевой VPS в `/tmp`, выполните:

```bash
cd /opt/xppn-agent && tar -xOzf /tmp/xppn-manager-v1.4.0-alpha-full.tar.gz xppn-manager-v1.4.0/deploy/upgrade-agent-on-vps.sh | bash
```

Скрипт сохраняет `/opt/xppn-agent/agent.env` и `/opt/xppn-agent/helper.key`, обновляет только `agent.py`, `helper.py`, Dockerfile, перезапускает `xppn-helper` и `xppn-agent` и оставляет резервную копию кода. **Remnawave, Nginx, сайты, firewall и SSL не меняет.** Этот скрипт предусмотрен для существующей установки со стандартными путями `/opt/xppn-agent` и не предназначен для ручной установки агента на чистом VPS.

## Ограничения и безопасность

1. Первый запуск нового стека всегда проводить на тестовом VPS. Изменение Compose/обновление ноды могут обрывать VPN-сессии.
2. Полная установка TLS/Nginx допускается **только на VPS без существующих Remnawave и Nginx**. Если Node уже есть, существующий TLS/SSL/fallback необходимо мигрировать отдельно; автоматическое добавление Nginx поверх неё не реализовано.
3. При доустановке из Agent-only через проектные действия Manager проверяет запущенный контейнер, затем пытается зарегистрировать его в Remnawave с выбранными inbound-ами. Если регистрация завершилась неопределённой ошибкой, проверь панель и только потом запускай ручной повтор; дубли запрещены. Для TLS используются профиль/inbound-ы выбранного шаблона или значения проекта.
4. Проектные Secret Key, API-токен и исходящий IPv4 панели нужны для установки. Требуется известный и подтверждённый исходящий IPv4 панели либо проверка через консоль панели.
5. Удаление агентских файлов или сброс ОС через Manager отсутствуют: это намеренное ограничение безопасности, а не скрытая кнопка.
6. Для старого helper без отчёта `capabilities` раздел сетевых настроек скрывается. Обновите агент локально на тестовом VPS.
7. Не копируйте в чат токены Remnawave, ключи нод или TOTP-секреты.

## Статус тестирования

Проверены `node --check`, `bash -n`, `python compileall`, 5 новых тестов логики наличия компонентов и API-блокировок с заглушками для недостающих пакетов, DOM-проверка интерфейса в headless Chromium (отсутствующие вкладки скрываются, формы раскрываются). Полный прогон зависимых от `pyotp`/`paramiko` тестов и реальный деплой в Remnawave/VPS в текущей среде не выполнен. Релиз Alpha.
